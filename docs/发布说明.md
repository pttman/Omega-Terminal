# 发布说明

## 仓库内容

保留 `src/`、`electron/`、实际使用的 `public/` 图标、字体及字体许可、`scripts/`、`tests/`、`docs/`、README、npm 清单与锁文件、TypeScript/Vite 和 Git 配置。

以下内容由 `.gitignore` 排除：依赖 `node_modules/`、编译输出 `dist/`、`release/` 和所有 `release-*/` 历史打包、`artifacts/` 发布资产、本机配置 `.local-data/`、未使用的设计稿 `.local-assets/`、npm/Electron 缓存、测试报告、日志、转储和环境变量文件。

用户主机、密码、密钥、AI 凭据和本机路径不属于源码或发布资产。测试里的本机 SSH/AI 服务和固定凭据仅为自动化测试夹具。

## Windows 发布流程

1. 更新 `package.json` 与 `package-lock.json` 中的版本，检查 README 的下载文件名。
2. 使用锁文件安装依赖，运行 `npm run check`。
3. 运行 `npm run release:zip`。`electron-builder` 只打包前端产物、桌面后端、离线手册、应用元信息、图标及生产依赖；ZIP 包包含完整运行目录。
4. 用真实打包程序验证，例如：

   ```powershell
   node scripts/app-dialogs-test.mjs --packaged "release/win-unpacked/Omega Terminal.exe"
   node scripts/ui-credentials-test.mjs --packaged "release/win-unpacked/Omega Terminal.exe"
   node scripts/motion-test.mjs --packaged "release/win-unpacked/Omega Terminal.exe"
   ```

5. 核对 ZIP 内容和 `SHA256SUMS.txt`，确认没有配置、缓存、测试报告或旧版本。
6. 提交源码前检查 `git diff --cached --stat` 与文件列表；打版本标签，然后发布 GitHub Release。仅上传版本化的 Windows ZIP 和校验文件，不把二进制包提交进 Git。
7. 验证远端标签、源码提交和 Release 资产一致。

## v0.1.0 预览版

- PowerShell、本地会话、SSH 指纹验证、密码与交互认证，以及 SFTP 上传。
- 拖动分屏、命令手册、兼容接口的 AI 助手及多套主题。
- 单一连接进度动画：输入密码时停在认证阶段，实际连接成功后才到达“连接成功”。
- 外观、登录信息和传输面板移出 1 秒自动收起，进出均有过渡。传输默认 3 条，展开保持固定高度并滚动。
- 右下角版本与关于信息；随主题变化的应用内退出确认，取消保留运行中的会话。
- Windows x64 ZIP 免安装，须完整解压运行；预览版未签名，不提供自动更新。
